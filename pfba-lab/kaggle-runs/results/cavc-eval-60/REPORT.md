## 5. 结论

1. **没有 Pareto 赢家。** 所有学习策略都显著牺牲 LAAL 换取 BLEU 和/或计算时间。相对 fixed：
   - A/C/E 的 BLEU 更高、completion 更低，但 LAAL 差 5–7；
   - B 的 LAAL 最接近 fixed（+0.79），但 BLEU 提升不显著（+1.43, CI 跨 0），时间还略慢；
   - D 与 fixed 的 BLEU 无显著差异（−0.77），时间快 4 s，但 LAAL 仍差 1.54。
2. **主要机制是 READ。** 未加 guard 的策略 READ 70–81%，连续 READ 最长 27–33 步；它们用“等源语”换 BLEU 和低计算，LAAL 自然变差。guard 本质上是手写的“必须写”约束：READ 降到 43–60%，LAAL 改善 4.4–5.0，但 BLEU 掉 1.1–5.1、时间上升。
3. **C（latency_focused）不是 A 的 Pareto 改进。** C vs A：BLEU −1.99（corpus），LAAL +0.78（不显著），completion −0.88（显著）。省了约 0.9 s/句，但没有质量或内容延迟上的净收益。
4. **成本项与评测指标不一致。** READ 在成本模型里是 0；延迟惩罚 `λ_l·backlog·advance` 远小于“多读带来的质量收益/计算节省”。网络因此学成“多读少写”。LAAL 衡量内容滞后，而 completion_s 是虚拟墙钟（含源语到达和计算），两者被优化成了相反方向。
5. **guard 不是统一策略。** 它和 checkpoint 强耦合：B（v3_baseline+guard）大量选 `b6h10`，D（latency+guard）大量选 `b6h4`；同一个 guard 产生完全不同的计算/质量结果。

## 6. 局限

- n=60，dev:0200–0259，是可行性切片，不是冻结 test；不能作为最终论文结论。
- 没有 COMET（需下载权重，未开启）。
- BLEU 的配对区间是句级 BLEU 的 bootstrap；交叉变体的 BLEU 只给了 corpus 差值，没有配对 CI。
- fixed `(4,6)` 与学习策略共享运行时，但 fixed 不做任何价值打分；这是匹配基线，不是“原始 TAF 论文数字”。
- guard 阈值是手写启发式，未训练。

## 7. 下一步建议

1. **把评测指标写进训练目标**：给 READ 增加等待/机会成本，或直接把“提交位置相对源语位置的滞后”做成 reward（近似 LAAL），而不是只惩罚 `backlog × advance`。
2. **改成约束优化**：在 `LAAL ≤ fixed` 的约束下最大化 BLEU / 最小化计算，用自适应拉格朗日乘子，而不是固定 `λ_t` 加权和。
3. **诊断 READ 位置**：统计句首 vs 句中 READ、连续 READ 长度与 LAAL 的关系；如果长 READ 集中在句首，说明策略在“等全文”，应直接限制。
4. **改进价值排序**：当前离线 Spearman 0.07–0.18、Top-1 ≤20%；考虑直接学边际价值 `ΔQ(s,a,a0)` 和 regret 诊断。
5. **扩大评测**：在更大的 dev holdout（n≈295）和冻结 `test:0140+` 上复现，再决定是否继续投入。
